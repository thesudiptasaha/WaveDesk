# WaveDesk — বড় ফাইল শেয়ারিং: আলোচনার নোট (২৬ অক্টোবর ২০২৬, রাত ১২:০৭)
**অবস্থা: শুধু আলোচনা, কোনো সিদ্ধান্ত বা কাজ নয়। ব্যবহারকারী বলেছেন "ফাইল শেয়ারিং পরে ভাবব"।** (আগের পরিকল্পনা: `file-management-plan.md` ও `docs/open-tasks.md`-এর "খ" অংশ।)

## প্রয়োজন (ব্যবহারকারীর উত্তর)
- ফাইল: কাঁচা ফুটেজ, অডিও ক্লিপ, ফটো; একাধিক ফাইল; ১০০MB থেকে ১০০GB।
- কোথা থেকে কোথায়: শুটিং লোকেশন/মাঠ থেকে অফিসের সার্ভারে (ক্যামেরা বা ফোন থেকে)।
- এখন WhatsApp: ধীর গতি, কম্প্রেশন, অগোছালো, তৃতীয় পক্ষ, আপলোড-ডাউনলোড অসুবিধা।
- অফিসে নিজস্ব NAS আছে; চাইলে নিজস্ব VPS/সার্ভারও বসানো যাবে।
- অ্যাপ থেকে সরাসরি আপলোড-ডাউনলোড চান।

## সত্য (সীমা)
মাঠ থেকে ১০০GB পাঠানো মাঠের মোবাইল ইন্টারনেটের আপলোড গতির ওপর নির্ভর করে; অ্যাপ তা বাড়াতে পারে না। বড় ফাইল বাস্তবে কার্ড/SSD হাতে এনে NAS-এ ঢালা হয়; মাঠ থেকে ছোট ফাইল পাঠানো বাস্তবসম্মত।

## বিবেচিত উপায়
1. NAS (অফিসের ভেতর LAN-এ দ্রুত; বাইরে থেকে VPN/সুড়ঙ্গ)।
2. ব্রাউজার P2P (WebRTC/PairDrop): দুজন একসাথে অনলাইনে; অন্য নেটওয়ার্কে TURN লাগতে পারে।
3. WebTorrent/টরেন্ট: এই টিমের জন্য লাভ কম, ফাইল জমা থাকে না — সুপারিশ নয়।
4. **Syncthing:** ফ্রি, P2P, থামলে নিজে চালু, কম্প্রেশন নেই। প্রতিটা ডিভাইসে আলাদা বসাতে হয়; অ্যান্ড্রয়েডে আছে, আইফোনে অফিসিয়াল অ্যাপ নেই; দুই প্রান্ত অনলাইনে থাকতে হয়; অ্যাপের অনুমতি-নিয়ম সার্ভারের ফোল্ডারে খাটে না। অফিসের দিকে "শুধু গ্রহণ (receive only)" রাখলে মাঠে মুছলেও অফিসে থাকে।
5. ক্লাউড/নিজস্ব স্টোরেজ (MinIO, Nextcloud, Cloudflare R2) + থেমে-চালানো আপলোড (`tus`, ব্রাউজারে Uppy): অ্যাপ থেকে সরাসরি আপলোড-ডাউনলোড; Vercel বড় ফাইল নিজে বইবে না, আপলোড সরাসরি সার্ভারে যাবে, Vercel শুধু অনুমতি দেবে।
6. Supabase Storage: ফ্রি প্ল্যানে ১GB, ভিডিওর জন্য অনুপযুক্ত; শুধু কাগজপত্র/রেফারেন্স।

## প্রস্তাবিত সমন্বয় (অনুমোদন বাকি)
- বড় ফাইল: Syncthing (ল্যাপটপ + অ্যান্ড্রয়েড) → অফিসের NAS; ফোল্ডারের নাম = কনটেন্ট আইডি (`CON-YYYYMMDD_NNN`)।
- ছোট ফাইল (ছবি, অডিও, আইফোন): অ্যাপ থেকে ব্রাউজার-আপলোড (tus) — পরের ধাপ।
- অ্যাপ: ড্রয়ারে "Files" তালিকা (নাম, আকার, কে/কখন, অবস্থা, ডাউনলোড); অফিস সার্ভারের ছোট সেতু-প্রোগ্রাম ফোল্ডার পড়ে ডেটাবেসে পাঠাবে।
- সরাসরি NAS-এ (বাইরে থেকে Cloudflare Tunnel/Tailscale) আগে; অফিসের ইন্টারনেটে সমস্যা হলে মাঝে VPS।
- Cloudflare-এর ফ্রি প্ল্যানে প্রতি অনুরোধে ~১০০MB সীমা এবং ভিডিও ট্রাফিকের শর্ত আছে: ব্যবহারের আগে যাচাই করতে হবে।

## খোলা প্রশ্ন (উত্তর হয়নি)
- অফিসের ইন্টারনেট আপলোড গতি, NAS-এর মডেল (Synology/QNAP), বাইরে থেকে পৌঁছানোর উপায় (পোর্ট খোলা বা সুড়ঙ্গ)।
- মাঠে কারা কোন ডিভাইসে (ল্যাপটপ/অ্যান্ড্রয়েড/আইফোন), মাঠের ইন্টারনেট গতি।
- ফাইল কতদিন রাখা হবে (মোছার নিয়ম); কারা কোন কনটেন্টের ফাইল দেখবে/নামাবে (ক্রেডিটে থাকা সদস্য + Owner + Manager প্রস্তাবিত)।
- ছোট পরীক্ষা: অফিসের NAS + একটা ল্যাপটপে Syncthing বসিয়ে একটা ফোল্ডার মেলানো (অ্যাপের কোড লাগে না)।

## সিদ্ধান্ত (২৬ অক্টোবর ২০২৬, দুপুর): স্টুডিও/মাঠের ফাইল রাখা — প্রথম ধাপ, নতুন সিস্টেম ছাড়া
- শুট: বেশিরভাগ অফিস স্টুডিওতে (ক্যামেরা); বাইরে আইফোন ও ক্যামেরা। ফাইল অফিসে ফিরে অফিসের শেয়ার্ড ড্রাইভে কপি হয় (NAS মডেল অজানা; সবার পিসিতে শেয়ার্ড ড্রাইভ)। Syncthing/আপলোড এখন লাগবে না।
- ফোল্ডার বানাবে ক্যামেরাম্যান (হাতে); অ্যাপ বানাবে না।
- **ফোল্ডারের নাম = শুধু কনটেন্ট আইডি** (ব্যবহারকারীর চূড়ান্ত সিদ্ধান্ত, ২৭ অক্টোবর; "ফোল্ডারে স্লাগ থাকবে না"; আগের "আইডি + স্লাগ" বাতিল): মূল `WAVECON-YYYYMMDD_XXXX` (৪ অঙ্ক); শর্ট = মূল ফোল্ডারের ভেতর সাবফোল্ডার `WAVECON-YYYYMMDD_XXXX-short_xxx` (৩ অঙ্ক)। স্লাগ বদলালেও ফোল্ডারের সাথে মিল ভাঙে না।
- নতুন Content ID ফরম্যাট `WAVECON-YYYYMMDD_XXXX` (ব্যবহারকারীর সিদ্ধান্ত; অ্যাপে এখনো `CON-YYYYMMDD_NNN`; Content ID কাজ আগে)। শর্টের শেষে `-short_xxx`।
- ড্রয়ারের হেডারে শুধু **"Copy ID"** বাটন (কনটেন্ট আইডি কপি; ২৭ অক্টোবরের সিদ্ধান্ত; আলাদা ফোল্ডার-নাম বাটন লাগবে না)। আইডি স্লাগের ডানে, স্লাগের কাছাকাছি বড় আকারে।
- "ফাইল জমা দিয়েছি" টিক: প্রডিউসার, ক্যামেরাম্যান, ম্যানেজার (ও Owner); একবারই; টিকে এডিটর নোটিফিকেশন + কে/কখন লগ।
- ক্রম: ১) Content ID (নতুন ফরম্যাট) ২) টিকসহ Production ট্যাব নকশা ও কাজ।
